## A0-JOB-01 — Frozen Python checkout launch

```text
read explicit project_path,python_path,case_path,new_output_dir
require project has pyproject.toml, uv.lock and src/fomhd
require python_path is executable
require case is a regular input
resolve project,python and case to absolute paths
set PYTHONPATH to project/src for the job process
set OPENBLAS_NUM_THREADS=1
require Python imports fomhd from project/src/fomhd
record Python,Cupy and Warp versions
record Python,pyproject,lock and case SHA-256 values
record SLURM_JOB_ID, CUDA_VISIBLE_DEVICES, host and UTC timestamps
invoke srun <python> -m fomhd run <case> --output <new-dir>
optionally append --restart <accepted-checkpoint>
keep all paths unchanged during the run
disable errexit around srun|tee and capture both PIPESTATUS entries immediately
return the first nonzero program, tee, or receipt status
never report success after an import mismatch, numerical failure, exit failure,
or incomplete launch receipt
```

The job uses ordinary user permissions and the user's own Slurm allocation. No
global environment, CUDA installation, device ACL, profiler, or scheduler
configuration is changed. GPU work is not moved to a login shell when resources
are unavailable. The run directory remains single-writer and retains exact
inputs, runtime source snapshot, checkpoints, diagnostics and failure evidence.

Python package versions come from the frozen checkout's matching environment.
The launcher records them but does not run `uv sync` from the job.
